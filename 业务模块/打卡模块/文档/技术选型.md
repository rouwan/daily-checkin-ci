# 打卡模块技术选型

> 状态：第一阶段已实施  
> 最后更新：2026-11-22

## 一、总体原则

业务保持单用户、单习惯和每日二元打卡。技术选型只服务于完整实现和后续架构训练，不通过增加业务功能提高复杂度。

前端、后端和数据库都属于同一个打卡业务模块。

## 二、前端选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 运行环境 | Node.js 当前长期支持版 | 支持 Vite 和前端构建 |
| 包管理 | npm | 随 Node.js 提供，不增加额外工具 |
| 框架 | Vue 3 | 页面少、入门成本低 |
| 语言 | TypeScript | 明确页面和接口的数据结构 |
| 构建工具 | Vite | 配置简单、启动快 |
| 样式 | 原生 CSS | 首版页面简单，不引入组件库 |
| 请求方式 | 浏览器原生 fetch | 不增加请求库 |

## 三、后端选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.12 | 业务代码直观，便于后续测试和拆分 |
| 环境与依赖 | uv | 统一虚拟环境、依赖和锁定 |
| 后端框架 | FastAPI | 请求校验、路由和接口文档能力完整 |
| 运行服务器 | Uvicorn | 与 FastAPI 配套 |
| 数据校验 | Pydantic | 由 FastAPI 使用，减少手工校验 |
| 接口形式 | HTTP JSON 接口 | 前端与后端保持明确边界 |
| 单元测试 | pytest | 以纯业务规则为测试边界，不依赖数据库或 HTTP |
| 接口测试 | FastAPI TestClient + httpx2 | 在进程内验证 HTTP 契约和临时数据库组合行为 |
| 冒烟测试 | Playwright + Chrome | 真实前后端下验证两条核心用户路径 |

## 四、数据库选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 数据库 | SQLite | 单文件、无需独立服务，满足首版数据量 |
| 访问方式 | Python 内置 sqlite3 | 首版不引入数据库映射框架，SQL 边界更直接 |
| 可视化工具 | DBeaver 社区版 | 支持 SQLite，也便于以后切换到 PostgreSQL |

数据库只允许后端直接访问。前端必须通过后端接口读写数据。

数据库可视化工具属于开发辅助工具，不随模块运行，也不放入 `功能模块/`。

## 五、技能选型

技能是人工智能编程脚手架的一部分，不是代码依赖。

| 技能 | 作用 | 使用阶段 |
| --- | --- | --- |
| `frontend-design` | 确定页面布局、信息层级、字体和色彩 | 前端设计前 |
| `vue` | 约束 Vue 3 组合式写法、组件和响应式代码 | 前端编码时 |
| `web-design-guidelines` | 检查响应式、可访问性和交互规范 | 前端提交审查前 |
| `webapp-testing` | 启动前后端、执行页面验收和核心冒烟测试并截图 | 页面验收与冒烟测试 |
| FastAPI 官方库技能 | 按实际安装版本约束后端实现 | 后端开发前 |

技能来源：

- [前端设计技能](https://github.com/anthropics/skills/tree/main/skills/frontend-design)
- [Vue 技能](https://github.com/antfu/skills/tree/main/skills/vue)
- [网页设计规范技能](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines)
- [网页验收技能](https://github.com/anthropics/skills/tree/main/skills/webapp-testing)
- [FastAPI 技能说明](https://fastapi.tiangolo.com/tutorial/#ai-agent-skills)

技能已按固定来源和版本安装到模块级 `技能/` 目录。安装记录见[技能安装记录](../技能/安装记录.md)。

## 六、运行关系

```text
浏览器
  ↓
Vue 前端
  ↓ HTTP JSON
FastAPI 后端
  ↓
SQLite 数据库

DBeaver 单独连接 SQLite，仅用于开发查看
```

## 七、CI 审查服务

- 双视角 PR 审查使用 DeepSeek Responses API。
- 该服务只在 GitHub Actions 审查流程中调用，不属于产品运行时依赖。
- PR 差异和必要的仓库上下文会发送到 DeepSeek；API Key 只保存在 GitHub Actions Secret 中。
- 产品页面、后端接口和 SQLite 数据流不经过 DeepSeek。

## 八、明确暂不引入

- 页面组件库和状态管理库。
- 数据库映射框架和迁移框架。
- 独立数据库服务。
- 登录、权限和多用户体系。
- 产品运行时的远程部署和外部服务。
- 与当前页面无关的第三方技能。

这些内容只有出现真实需要时才重新讨论。
