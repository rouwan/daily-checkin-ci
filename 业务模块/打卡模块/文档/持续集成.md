# 持续集成

> 状态：第二阶段已完成  
> 最后更新：2026-11-22

## 目标

使用 GitHub Actions 在公开仓库中自动验证当前单模块的工程质量。

CI 覆盖：

- 后端 23 个纯单元测试。
- 14 个单模块 HTTP 接口测试。
- Vue TypeScript 检查和 Vite 生产构建。
- 两条真实浏览器核心冒烟路径。
- 双视角审查汇总器的纯 Python 单元测试。

CI 不替代多模块接口测试、正式人工审查或持续交付。多模块和项目管理中台暂缓。

仓库另有一个独立的
[`双视角代码审查`](../../../.github/workflows/code-review.yml)
工作流，用于给出建议型 PR 反馈，不替代本文件描述的测试门禁。

## 触发条件

- 推送到 `main`。
- 提交到 `main` 的拉取请求。
- 手动触发。

同一分支的新运行会取消尚未完成的旧运行。

## 任务分层

| 任务 | Runner | 内容 |
| --- | --- | --- |
| `质量检查` | `ubuntu-latest` | 单元测试、接口测试、前端生产构建 |
| `核心冒烟测试` | `windows-latest` | 启动真实前后端，执行两条浏览器路径 |

冒烟测试在质量检查通过后执行。

## 测试隔离

- 单元测试不连接数据库、不启动接口、不启动前端。
- 接口测试使用进程内 FastAPI 客户端和独立临时 SQLite。
- 冒烟测试使用系统临时目录中的 SQLite，并在结束后清理。
- 正式 `打卡.sqlite3` 不进入公开仓库，也不参与 CI。

## 浏览器模式

本机冒烟测试默认使用已安装的 Chrome。

CI 设置：

```text
CHECKIN_SMOKE_BROWSER_CHANNEL=bundled
```

该模式使用 Playwright `1.60.0` 安装的 Chromium，不依赖 runner 预装 Chrome。

## 本地复现

后端测试：

```powershell
cd "业务模块\打卡模块\功能模块\后端"
uv sync --frozen
uv run pytest -m unit -q
uv run pytest -m interface -q
```

前端构建：

```powershell
cd "业务模块\打卡模块\功能模块\前端"
npm ci
npm run build
```

冒烟测试：

```powershell
cd "业务模块\打卡模块"
.\测试\冒烟\运行冒烟测试.ps1
```

## 安全边界

- 工作流权限只保留读取仓库内容。
- Pull Request 不读取仓库 Secret。
- 第三方 Action 固定到完整提交 SHA。
- 不使用自托管 Runner。
- 公开文件不包含 API Key、正式数据库或本地学习记录。

双视角审查工作流使用单独的 `DEEPSEEK_API_KEY` Secret、只读 sandbox 和独立评论权限，详细边界见[代码审查agent](./代码审查agent.md)。

## 失败排查

1. 先查看失败任务和第一个失败步骤。
2. 后端测试在本地按测试类型复现。
3. 前端失败时先运行 `npm ci`，再运行 `npm run build`。
4. 冒烟失败时确认 `8000` 和 `5173` 端口空闲。
5. 检查运行日志中的临时数据库路径、服务启动和浏览器错误。
