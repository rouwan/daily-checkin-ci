# 单模块接口测试

> 状态：第一阶段已实施  
> 最后更新：2026-11-22

## 阶段定位

单模块 HTTP 接口测试作为第一阶段范围的一部分完成。

第四阶段仍然保留，用于加入多模块后的模块接口和模块间接口测试。

## 测试边界

- 使用 FastAPI `TestClient` 在进程内调用应用。
- 不启动 Uvicorn，不监听真实网络端口。
- 不启动前端或浏览器。
- 每个测试使用独立临时 SQLite 数据库。
- 测试不读写正式 `功能模块/数据库/打卡.sqlite3`。

这组测试验证 HTTP 契约、请求校验、业务服务和临时数据库的组合行为。

测试/

## 测试数据隔离

`conftest.py` 为每个测试设置独立的 `CHECKIN_DATABASE_PATH`。

应用生命周期启动时会在 pytest 临时目录中初始化数据库。测试结束后，环境变量恢复，临时数据库由 pytest 清理。

## 覆盖行为

| 行为 | 验证内容 |
| --- | --- |
| 空状态 | 未设置习惯时返回空习惯、未打卡和连续零天 |
| 设置名称 | 合法名称写入并清理首尾空白 |
| 名称上限 | 40 个字符可以保存 |
| 非法名称 | 空值、纯空白和 41 个字符返回 `422` |
| 打卡前置条件 | 未设置习惯时打卡返回 `409` |
| 首次打卡 | 返回已打卡状态和连续一天 |
| 重复打卡 | 两次调用仍成功，数据库只有一条今日记录 |
| 空撤销 | 今天没有记录时撤销仍返回成功 |
| 正常撤销 | 打卡后撤销，状态恢复为未打卡 |
| 修改名称 | 打卡后改名不会删除打卡状态 |
| 持久化 | 新建测试客户端后仍能读取之前写入的数据 |
| 健康检查 | `/api/health` 返回正常状态 |

共 14 个接口测试用例。

## 运行方式

从后端目录运行：

```powershell
cd "业务模块\打卡模块\功能模块\后端"

# 只运行接口测试
uv run pytest -m interface -v

# 只运行单元测试
uv run pytest -m unit -v

# 运行全部自动化测试
uv run pytest -v
```

依赖使用 FastAPI 当前版本推荐的 `httpx2` 测试客户端。

## 暂不覆盖

- 前端是否调用了正确接口。
- 浏览器跨域行为。
- 页面按钮与接口的真实串联。
- 页面布局、键盘操作和响应式。
- 真实前后端下的完整用户流程。

前端页面验收继续负责布局、键盘和响应式；两条核心用户流程已由[冒烟测试](./冒烟测试.md)覆盖。
